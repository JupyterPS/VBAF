# Contributing to VBAF

Thank you for considering a contribution to VBAF.
All contributions are welcome — new pillars, bug fixes, documentation, tutorials.

## Ways to Contribute

- Add a new enterprise pillar (Phase 28+)
- Fix a bug and submit a pull request
- Improve documentation or tutorials
- Share a case study from your own environment
- Report an issue on GitHub

## Getting Started

1. Fork the repository on GitHub
2. Clone your fork locally
3. Create a feature branch
```powershell
git checkout -b feature/your-feature-name
```

4. Make your changes following the coding standards
5. Test your changes
6. Commit with a clear message
```powershell
git commit -m "Phase 28: NetworkTrafficManager — +115% improvement"
```

7. Push and open a pull request

## Pull Request Guidelines

- One feature or fix per pull request
- Include a description of what changed and why
- All enterprise pillars must include a benchmark result
- All new functions must be documented in API-Reference.md
- Follow PS 5.1 coding standards

## Reporting Issues

Open an issue on GitHub with:
- PowerShell version (`$PSVersionTable.PSVersion`)
- Windows version
- Error message and stack trace
- Minimal reproduction steps

## Code of Conduct

Be respectful. Be constructive. Help others learn.
VBAF is built by practitioners for practitioners.
